## B05：模型故障后的交付与恢复

原始问题有两条：模型连接成功后返回 401，生成报告被整体阻断；回答已经落盘，模型续问失败却向界面返回整体失败，容易引导重复提交。

原始红探针通过内存载入 Git 基线 controller 并注入 prompt 401 验证：报告请求返回 `AUTH_FAILED` 且报告数为 0；回答请求同样报错，但事实已经增加、版本已更新、问题已推进。修复验证另外使用真实 Pi SDK 和本机合成 HTTP 服务。

现在的行为：

- 始终提供「生成本地简报」。`reportLocal` 不调用模型，计算和已保存自述照常交付，报告明确标识没有 AI 解读。
- 正常报告请求遭遇鉴权、额度、超时、断连、模型不可用或轮次上限时，自动交付当前事实的本地简报，并保存故障原因提示。
- 模型已经保存当前完整报告后再失败，保留该报告与 AI 解读，提示报告已保存。旧版或另一段睡眠的报告不能充当成功结果。
- 用户主动取消报告时不自动生成；领域输入和本地存储错误继续返回失败，不用本地简报掩盖错误。
- 答案保存后续问失败或取消，返回「回答已保存」状态。`retryFollowup` 只重试后续模型步骤，不再次写入原答案。
- 「继续本地问询」保存本地模式，后续答题不请求模型；「恢复 AI 续问」可以切回。报告是否调用模型仍由所选报告入口决定。
- 通知按调查、睡眠段、事实版本及待答问题约束，重开仍保留；更正、换题或删除后失效，跨调查不串用重试目标。模型错误文本仅保留安全错误码。
- 模型故障通知存在时，头部显示警示状态和原因，保留配置供恢复。

## B06：事实与报告字段一致

原始红测试复现工具接受 `sleep_duration=大概六到七小时`、`waking_feeling=醒来累`，报告仍显示资料不足。修复从字段约定、持久化读写和报告呈现三处贯通：

- 统一核心字段：`sleep_duration_hours`、`remembered_awakenings`、`recovery`，明确作用域、数值类型与单位；系统提示、工具 schema、宿主 Skill 使用相同约定。
- 受控兼容 `sleep_duration`、`wake_feeling`、`waking_feeling`。宽泛的 `sleep_complaint` 保留为自定义事实，不擅自解释成恢复感。
- 初次回答、事实更正、模型工具共用解析。明确数值和单位可以换算；范围保留上下界，近似和未知保留原话，不生成中点或猜测精度。
- 桌面时长和夜醒输入允许文本；「不知道 → 更正为 6.5」恢复数值类型。中文数字、英文数字、小时/分钟单位及范围均有专项；日期、钟点、叙事、混合单位等保守保留原文。
- 每份新报告保存生成时的 `reportedFacts`，界面和 Markdown 可回看核心字段、自定义事实及不确定原话。历史报告不借用当前事实。
- 旧库事实原始行保持不变，读取时将同义字段投影为当前值，按时间、修订和确定性顺序选择；未知更正可覆盖旧值。删除当前事实会删除同义组，避免旧别名复活。
- 受影响旧报告标为需要更新，历史计算内容保留；迁移有事务、幂等标记和失败回滚测试。旧固定题可以清理，自定义澄清继续保留。

独立审查另外修复了英文近似表达被精确化、合法自定义字段命中对象原型、旧别名导致重复固定题三个边界。

## 真实 ChatGPT 订阅补测

沿用用户已授权的 EvalPi OAuth，通过其 Pi SDK 1.0.0，运行当前 SleepClaw 系统提示、工具和领域实现。只使用合成输入；没有复制或输出凭证，没有在用户输入中追加规范字段名提示。

模型 `openai/gpt-6.1-sol`，**5/5 场景通过**，共 26 次模型响应、21 次工具调用，约 193 秒：

| 输入场景 | 最终事实与报告 |
| --- | --- |
| 中文六到七小时，醒来很累 | 6～7 小时范围和恢复感进入固定栏目，无精确时长 |
| 精确 7 小时，醒来很累 | 420 分钟与恢复感进入固定栏目 |
| 英文 5～6 小时，醒来疲惫 | 范围和恢复感保留，无中点 |
| 大概七小时，醒来精神还好 | 保留 approximate，不产生精确时长 |
| 完全记不清时长，疲惫，窗外施工 | 时长保持未知/不确定；恢复感与额外背景均出现在事实回顾 |

可复用脚本：[eval-b06-subscription.mts](../../pi-app/scripts/eval-b06-subscription.mts)。需要显式设置 `EVALPI_PROJECT` 指向已有登录的 EvalPi 项目。此项使用外部订阅测试接入，未覆盖 SleepClaw 桌面的 OAuth 登录；5 个场景用于修复冒烟验证，不能估算所有自然语言输入的通过率。

## 实际桌面验收

真实 Electron + Playwright，独立 `SLEEPCLAW_HOME` 和 userData，本机合成服务先完成连接测试，随后返回 401：

1. 保存年龄，界面显示答案已保存及鉴权失败。点击仅重试续问，事实列表和版本不变。
2. 切到本地问询，填写作息、六到七小时、跳过夜醒、填写恢复感；事实保留范围元数据。
3. 点击正常报告，模型失败后自动进入本地报告；报告显示 6～7 小时和醒来很累，无精确时长指标，明确缺少 AI 解读。
4. 完整关闭重开，故障通知、本地模式和报告保留。
5. 在事实更正界面将时长改为「不知道」，再更正为 `6.5`；生成本地简报得到 **390 分钟**。旧范围报告标为需要更新，历史内容不变。
6. 恢复 AI 续问，保存另一条合成背景；故障提示再现。让合成服务恢复后点击仅重试续问，通知清除，事实及版本不变。

开发热更新曾使自动化等待导航超时，稳定代码后重新加载测试窗口完成了剩余验收；未把这次点击超时记为产品模型故障。控制台 0 错误，有既有开发模式 CSP 提示。测试应用和合成服务已关闭。
