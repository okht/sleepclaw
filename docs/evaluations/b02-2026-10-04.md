# B02 修复与专项评测

日期：2026-10-04，Asia/Singapore。基线：`fd51aedafb0f0b53a0c6fe1e4959899b81598ea4`，包含已发布的 B01 修复。

## 问题与结果

原案例：同一调查先分析 A 晚，记录「睡了 7 小时、醒来头痛」，再换到 B 晚。旧实现的睡眠事实仅按调查 ID 保存，换时段只让报告失效，因此 B 报告仍带入 A 晚的 420 分钟和恢复感。

先新增合成 XML → A 晚自述 → B 晚报告的回归案例，修复前实际失败，B 报告出现 `selfReportedSleepMinutes=420`。修复后，B 晚设备睡眠仍为 480 分钟，自述时长缺失，报告及 JSON 导出均无 A 晚头痛内容。切回 A 晚可恢复原自述；B 晚另存的 8 小时也独立保留。

## 修复契约

- 每段睡眠具有持久化的 `sleepEpisodeId`。所有单次睡眠事实按该 ID 保存，包含数值、文字、布尔值、unknown 和 uncertainty；个人档案继续共享。
- 同 scope 下，以第一次选中的时间范围作为固定归属参照。精确匹配优先；两个区间重叠长度严格大于二者较长时长的 50%，且只有一个历史匹配时，视为同一睡眠。小幅纠正边界保留自述，同晚切换设备来源也保留。
- 无匹配或同时匹配多段历史睡眠时，使用独立上下文。50% 边界、微小重叠、长窗口桥接和连续滑移都不能逐步携带旧晚事实。这个阈值用于信息归属，属于保守产品规则。
- 首次选择设备范围可以绑定已存在的无时段自述。scope 改变会隔离。切回原范围恢复原事实；其他晚的事实保留在数据库中。
- 真实目标变化重新生成待答问题，跨睡眠清除旧计划；完全相同的规范化目标为无操作，避免无故增加版本。
- Pi 会话按睡眠保存和恢复。旧会话绑定的工具在换晚后无法继续写入。模型调用 `sleep_target` 换晚时，结束旧轮并在新睡眠上下文继续原请求，最多 3 次会话尝试，共享 120 秒和 12 轮预算。
- 工具上下文仅返回当前睡眠的报告和反馈。初始调查目标保留在初始睡眠中；其他睡眠不继承目标里的症状文字，调查发现列表也不再携带历史目标文本。
- 界面报告列表和聊天中的报告入口跟随当前睡眠；新晚没有报告时显示空状态。分析依据页解释自述、聊天和报告的归属及返回方式。
- v1 数据迁移为初始睡眠，事实原行保留。没有睡眠 ID 的旧报告，仅在明确存在 `basis` 且时间、scope 与当前初始睡眠一致时进入当前上下文；无法确定归属的报告和反馈不进入模型上下文。

## 结论边界

本次在覆盖范围内未观察到回归，连续组合测试支持跨时段、来源、scope、重启等场景的归属稳定性。有限合成案例无法证明所有真实输入，也不等于真实模型判断质量已经验证。Pi 专项使用真实 SDK 和本地合成模型服务，检查实际发送的请求与工具副作用；本次没有追加 ChatGPT 订阅模型调用。

升级前已混写在同一事实行、且没有日期归属的自述，迁移无法自动判断属于哪一晚，只能保留到当时已选范围。旧会话也可能已包含这种历史混写。后续选择不同睡眠会隔离，历史错误内容仍需用户纠正。

时间归属规则可能把幅度较大的边界纠正保守分为新睡眠；返回原时段可找回旧信息。CLI/MCP 宿主仍需按工具契约使用当前事实，桌面的会话重启防护不等于能清除外部宿主自身的聊天历史。B03–B06 的完整问题范围未在此次验收。
