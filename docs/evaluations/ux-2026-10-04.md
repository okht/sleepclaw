# UX 与 ChatGPT 订阅登录修复验证

日期：2026-10-04。基线：`ecb56f4`，原有 B01–B06 回归 575 项。全部睡眠输入为合成数据。

## 修复范围

| 问题 | 修复后的行为 |
| --- | --- |
| 聊天展示内部英文编排指令 | Pi 会话以原生 custom entry 记录用户原文、跳过、报告和重试操作；完整 prompt 指纹绑定只隐藏应用生成的内部指令。离线回答立即持久化，重启仍可读。 |
| 模型无理由重问 | `sleep_question` 对同一范围内已知或已跳过的字段统一别名检查；必要澄清需给出具体理由，错误结果提供可执行提示。 |
| 两条建议均被拒后重复推荐 | 同一睡眠的相同行动采用最新反馈；两条内置建议都被拒绝后停止新增建议。中英文切换、其他睡眠反馈不会绕过约束。 |
| 反馈只显示笼统成功 | 报告显示已选择的反馈及备注，按钮呈现选中状态；可以改选或更新相同选择的备注。 |
| 计划与进度不可理解 | 显示短计划、步骤状态及过期提示；工具名称转换为用户可读进度。 |
| 导入、连接没有全局取消 | 导入、模型连接、授权显示进度与取消；聊天任务的状态合并到输入区，仅保留一个停止按钮。切到其他页面时取消入口移至顶部；导入取消准确说明事务回滚，已保存事实保留。 |
| 删除提示范围不准确 | 明确说明报告、反馈、导出和模型历史的清理范围，以及原始导入文件保留。 |
| 桌面缺少订阅登录 | 增加 ChatGPT 订阅/API Key 两种入口，浏览器授权、手动回调、取消、切换模型、失效重连及退出。 |
| 授权页面名称显示 Pi | 官方授权链接仅将 `agent_name_hint` 改为 `SleepClaw`；用户已确认页面名称并完成重新授权。其余认证参数保持原值。 |

## 认证与实现边界

- Pi 依赖及独立桌面运行时锁文件从 0.86.1 更新至 1.0.0，使用原生 `openai` ChatGPT OAuth。开发中确认旧 `openai-codex` JWT 流无法直接复用 EvalPi 的 direct-token 登录态，未把它当作成功接入。
- 稳定的安装级 UUID 持久化于本机设置，通过 SDK 的 `getDeviceId` 提供。Pi 继续负责 PKCE、state、回调、令牌交换、刷新和模型执行。
- `chatgpt-auth.bin` 由 Electron safeStorage 加密。令牌更新只走主进程与 utility worker 私有消息，收到持久化确认后才更新内存；无 token、授权码或回调进入渲染状态、聊天和报告。
- 覆盖刷新/退出并发、晚取消、持久失败、负确认和超时、已删除凭据后的 SDK 后置失败。原生 SDK 包装的存储错误保留应用安全错误码。
- 工具异常只向模型提供安全错误码和恢复提示，保留 failed-tool 语义，避免原始本机错误文本进入模型请求。
- CLI 保持原有 API Key 接口，不解密桌面订阅凭据。

| 反馈 | 原因与修复 |
